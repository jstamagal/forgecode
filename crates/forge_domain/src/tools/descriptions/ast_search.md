Search code structurally with ast-grep (in-process, tree-sitter grammars). Patterns match parsed syntax, so they span whitespace and line breaks and never match inside comments or strings.{{#if tool_names.fs_search}} Use `{{tool_names.fs_search}}` for plain text, regex and filenames.{{/if}}
- In a pattern `$NAME` matches one syntax node and `$$$NAME` matches zero or more; metavariables are uppercase, and reusing one requires equal captures.
- The language is inferred from each file's extension; set `language` to restrict the search to one language. Under `language="c"` a bare call pattern like `call($A)` matches nothing, because tree-sitter-c parses that fragment as a type; write it as an expression statement (`call($A);`).
- Matches come back as an absolute `path:line` heading, the numbered source lines (`12|code`), and the metavariable captures. When more matches exist than `max_results` (default 200), the extra ones are dropped and the result says so.
- The walk skips paths ignored by `.gitignore` and hidden paths.
- Rewrites are two-step: `rewrite` alone is a dry run that shows a unified diff and changes nothing; `apply=true` writes it and is refused when there are more matches than `max_results`. An applied rewrite snapshots every changed file first{{#if tool_names.undo}}, so `{{tool_names.undo}}` brings each back{{/if}}.
